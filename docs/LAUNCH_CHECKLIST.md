# Launch checklist (owner actions)

Everything in code is done on branch `redesign-2026-10`. These steps need
your accounts, so no session could do them. In priority order.

## 1. Security: before or right after merging

1. **Revoke the leaked SSH key.** `gitkey` (an OpenSSH private key) was
   committed to this public repo. It is deleted from the tree, but it stays
   in git history and anyone may have copied it. Remove it from GitHub →
   Settings → SSH and GPG keys, from every repo's Deploy keys, and from
   `~/.ssh/authorized_keys` on any server that trusted it. Once revoked it is
   harmless; purging history is then optional.
2. **EmailJS dashboard** → Account → Security: restrict allowed origins to
   `https://fareskhanchouch.com`. Turn on reCAPTCHA only if spam arrives.

## 2. Deploy

3. Merge the PR; Vercel deploys `main`.
4. **Vercel → Project → Domains:** make `fareskhanchouch.com` the primary
   domain; have `www.fareskhanchouch.com` and `fares-khanchouch.vercel.app`
   redirect (308) to it, so search engines see one site, not three.
5. Open `https://fareskhanchouch.com/sitemap.xml`, `/robots.txt` and
   `/resume.pdf` and check they load.

## 3. Get indexed (about 30 minutes, once)

6. **Google Search Console** (search.google.com/search-console): add a
   *Domain* property for `fareskhanchouch.com` and verify it with the DNS TXT
   record it gives you (at your domain registrar, or in Vercel if Vercel
   manages the DNS). Then:
   - Sitemaps → submit `https://fareskhanchouch.com/sitemap.xml`.
   - URL Inspection → paste `https://fareskhanchouch.com/` → Request
     indexing. Repeat for `/writing/grounded-llm-generation`.
   - (Alternative to DNS: set the Vercel env var
     `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION` to the meta-tag code and redeploy.)
7. **Bing Webmaster Tools** (bing.com/webmasters): "Import from Google Search
   Console". This covers Bing, DuckDuckGo, Yahoo, and the AI search
   engines that use Bing's index (ChatGPT search, Copilot).
8. Optional, after later content changes: `npm run indexnow` pings Bing and
   other IndexNow engines (the key file is already in `public/`).

## 4. Connect your profiles (this is what ranks your name)

Search engines decide which site is "you" from consistent links between your
profiles and the site. The site already links out with `rel="me"` and lists
GitHub and LinkedIn in its structured data; the links back complete the
loop.

9. **LinkedIn:** Edit intro → Contact info → Website → add
   `https://fareskhanchouch.com` (type: Portfolio). Add the site and the
   write-up to your Featured section.
10. **GitHub:** Profile → Edit profile → Website: `https://fareskhanchouch.com`.
    Add the link to your profile README, and set it as the Website on the
    `n8n-operator` repo (About → gear icon).
11. Share the write-up once as a LinkedIn post. Before posting, paste the URL
    into LinkedIn's Post Inspector (linkedin.com/post-inspector) so the
    preview card is fresh.

## 5. Check the result

12. Run the home page and the write-up through Google's Rich Results Test
    (search.google.com/test/rich-results) and validator.schema.org. Expected:
    Person, ProfilePage, WebSite and Article detected, no errors.
13. After 1–2 weeks: Search Console → Performance → query "fares
    khanchouch". Pages → look for "Discovered – currently not indexed" and
    request indexing again if needed.

## Notes

- If you cross-post the write-up (dev.to, Medium), set its canonical URL to
  the article on this site.
- When content changes, bump `site.updated` in `src/data/index.ts` (feeds the
  sitemap's lastmod and the structured data).
- The public résumé (`public/resume.pdf`) is generated by the job-search MCP
  from `samples/website/public_resume.payload.json` in that repo: client names
  are replaced ("a Qatari bank") and there is no relocation/notice line.
  Regenerate it the same way when the vault changes.
